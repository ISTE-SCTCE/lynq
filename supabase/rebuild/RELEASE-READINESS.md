## Required approval contract

Website -> membership_registrations -> NDC/admin review with official KE104xxx ID
-> atomic allocation -> canonical membership -> apps refresh from shared backend.
The official ID is entered by reviewer; NEVER autogenerated.

Local manage-membership-registrations now requires membershipId and calls
approve_membership_registration(p_registration_id uuid, p_membership_id text,
p_reviewer_id uuid). This RPC is NOT implemented/deployed yet. Do not deploy this
endpoint before its dependency and authorization tests pass.

The transaction must:
1. Verify reviewer against approved server-owned permissions, not user-editable profile role.
2. Lock the pending registration and existing user/membership candidates.
3. Validate complete details, payment verification and official ID uniqueness.
4. Resolve identity without rewriting existing Auth/profile UUIDs or name-only merging.
5. Create/attach canonical user and membership, duration and forum affiliations.
6. Mark registration approved with actor/date only after allocation succeeds.
7. Return {id, membership_id, status:'approved'}, idempotently for an identical retry;
   conflicting repeat requests fail with no partial changes.
8. Write audit/provenance and a controlled legacy compatibility update in the same transaction.
